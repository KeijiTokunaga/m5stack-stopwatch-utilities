# M5Stack StopWatch Utilities

StopWatch C152がWi-Fiで為替APIへ直接接続し、同意した場合は周辺Wi-Fiから推定した現在地をGoogle Mapsで表示します。

**StopWatch → 自宅Wi-Fi または iPhoneのインターネット共有 → GMOコイン外国為替FX API**

iPhoneに専用アプリ・Expo Go・開発用の署名は不要です。`firmware/` が現行版です。以前のSwift/BLE版は別フォルダに残っていますが、今回の構成では使用しません。

## アプリ選択

どの画面でも**黄色ボタン長押し**で選択画面を開きます。黄色短押しで次の項目、青色短押しで起動。項目のタップでも起動できます。

1. ドル表示アプリ
2. 水槽アプリ
3. 電池残量表示
4. Wi-Fi設定
5. ポモドーロ
6. Weather（大阪市の天気・時計）
7. Paradise（育成ゲーム）
8. Location（現在地の推定地図）

起動時はドル表示です。Wi-Fi未登録の場合は設定画面を開きますが、黄色長押しで抜けてオフライン対応アプリを使えます。Wi-Fi設定を抜けると設定用APを停止します。ドル表示以外では通常の為替通信を停止し、WeatherとLocationは表示中だけ各通信を行います（通信中の処理はタイムアウトまで待つ場合があります）。

### 水槽アプリ

[既存のMedaka](https://github.com/KeijiTokunaga/m5stack-stopwatch-medaka)を統合。メダカ・ネオンテトラ・グッピー各3匹、波・水草・気泡・4分間の照明変化を含みます。

- 黄色短押し：左にエサ6粒。青色短押し：右にエサ6粒。
- タップ：波。画面長押し：照明変化を固定／再開。
- 傾ける・揺らす・ひねる：IMUで水面に反映。
- 60秒間操作や動きがなければ減光し、描画を最大5fpsに抑えます。画面は消しません。
- 別アプリの表示中は水槽を一時停止し、戻ると続きから再開します。再起動時は初期状態です。

### ポモドーロ

[既存のポモドーロ](https://github.com/KeijiTokunaga/m5stack-pomodoro)を統合。集中25分、短い休憩5分、集中4回完了後は長い休憩15分。次の区間は停止状態で待ちます。

- 黄色短押し／中央の時間表示をタップ：開始・一時停止。
- 青色短押し：現在の区間をリセットして停止（集中完了回数は保持）。
- 青色長押し：全体を集中25分・完了0回・停止・音ONへ初期化。
- 下部のSOUND表示をタップ：音ON/OFF（振動は残ります）。
- NEXTをタップ：次の区間へスキップ。集中完了数には加算しません。
- 黄色長押し：アプリ選択。元アプリの黄色長押しによるスキップをNEXTへ移しました。
- 他アプリや選択画面の表示中、画面消灯中も計測を続けます。区間終了時は3秒間の音・振動で通知します。
- 操作時・区間終了時・計測中60秒ごとに状態を保存。再起動後は保存時点で一時停止し、電源OFF中の時間は数えません。最大約60秒の進捗を失う場合があります。

## 初回設定

1. **黄色長押し → Wi-Fi設定**で開きます（ドル表示中は青色長押しでも開けます）。保存済み接続先がなければ起動時に自動で開きます。
2. スマホまたはMacでWi-Fi **StopWatch-FX** へ接続。本体に表示されるパスワードを使用します。
3. ブラウザで **http://192.168.4.1** を開きます。
4. 「自宅Wi-Fi」「iPhoneのインターネット共有」を登録します。どちらか1件でも使用可能です。
5. 保存すると本体が再起動します。スマホ／Macは通常のWi-Fiへ戻してください。

iPhone共有のSSIDはiPhoneの名前、パスワードは「設定 → インターネット共有」の「Wi-Fiのパスワード」です。名前・パスワードをチャットへ送る必要はありません。

同じSSIDでパスワード欄を空欄にすると以前のパスワードを維持します。SSID欄を空欄にするとその接続先を削除します。設定APは2分で終了し、通常の接続先パスワードを画面やログへ表示しません。既存ファームウェアの単一Wi-Fi設定は自宅枠として引き継ぎます。

### Locationの設定とプライバシー

Locationは別途、`proxy/` をVercelへ配置し、設定画面へHTTPS URLと端末トークンを入力して明示的に同意した場合だけ動作します。操作時に周辺Wi-FiのBSSID・電波強度・チャンネルがプロキシ経由でGoogleへ送られ、通信先は通信に必要なIPアドレスを扱います。SSIDとWi-Fiパスワードは送信しません。推定位置と地図JPEGはRAMだけに置き、端末へ永続保存しません。黄色短押しまたはタップで再取得し、青色短押しでGoogle Mapsを開くQRコードと地図を切り替えます。精度は保証されないため画面に推定誤差を表示します。

Google APIキーと地図署名secretはプロキシだけに設定し、ファームウェアへ埋め込みません。導入手順は [`proxy/README.md`](proxy/README.md)、仕様・Google公式資料は [`docs/google-wifi-location-research.md`](docs/google-wifi-location-research.md) を参照してください。同意を取り消すにはWi-Fi設定でチェックを外して保存します（保存済みのLocation URL・端末トークンも削除されます）。

## 外出先

iPhoneの「設定 → インターネット共有」で、**「ほかの人の接続を許可」「互換性を優先」**をオンにします。StopWatchが接続するまでこの設定画面を開いておいてください。互換性を優先すると2.4GHzで接続できます。

StopWatchは接続開始時に自宅Wi-Fiを最大8秒試し、接続できなければiPhone共有を最大8秒試します。両方失敗したらWi-Fiを止め、画面が有効な間は60秒空けて再試行します。スリープから復帰すると再度接続を試します。接続済みのiPhoneから自宅Wi-Fiへ強制切り替えはしません。次回接続時に自宅を優先します。

Apple Watch / Instant Hotspotのように本体からiPhoneの共有を自動起動する機能はありません。携帯回線・契約のテザリング対応が必要です。

## ドル表示の操作と省電力

| 操作・状態 | 動作 |
| --- | --- |
| 黄色長押し（全画面） | アプリ選択画面 |
| 選択画面で黄色短押し／青色短押し | 次の項目／選択したアプリを起動 |
| 青色短押し／通常画面の黄色短押し／タップ | 更新要求 |
| 青色長押し／通常画面のタッチ長押し | Wi-Fi設定 |
| 電池使用中・通常 | 表示中は5秒ごとに取得 |
| 電池20%以下 | 15秒ごとに取得、明るさを下げる |
| 電池10%以下 | 手動更新のみ（起動時は1回要求） |
| 無操作15秒／30秒 | 減光／画面スリープ・通信停止 |
| 充電中 | 画面維持・5秒ごとに取得 |
| 電池画面 | 通常のAPI通信を停止 |

通信中のHTTP/TLS処理は短いタイムアウトを設定しています。消灯・電池画面に切り替えた際、処理中なら終了後にWi-Fiを停止するため数秒かかる場合があります。Wi-Fi設定APは独立して2分間有効です。CPUは通常80MHz、HTTPS通信中のみ240MHzへ上げ、終了時に80MHzへ戻します。BLE・マイクは起動しません。IMUは水槽用、スピーカー・振動はポモドーロの通知用に初期化します。ディープスリープではありません。持続時間・電流は未測定です。

表示はUSD/JPYのBID・ASK中間値（MID）、BID/ASK、直近120件のグラフ、日本時間の配信日時です。レートはGMOコインの提示値で、取引や注文は行いません。グラフの横軸は受信順です。受信から15秒超または配信時刻から30秒超で `STALE / LAST QUOTE` を表示します。エラー時は最後の値を保持し、API失敗は30秒間隔で再試行します。APIがメンテナンス応答（status=5）を返す場合は `API MAINTENANCE` と表示します。

## 開発・検証

```sh
rtk proxy pio run -d firmware
rtk proxy pio device list
rtk proxy pio run -d firmware -t upload --upload-port <確認したポート>
rtk proxy clang++ -std=c++17 -I firmware/src -I firmware/.pio/libdeps/m5stack-stopwatch/ArduinoJson/src firmware/test/logic.cpp -o /tmp/fx-hotspot-tests
rtk proxy /tmp/fx-hotspot-tests
```

USBシリアル115200 baudで `?` を送るとWi-Fi、接続先（0=自宅、1=iPhone、-1=なし）、通信状態、電池、明るさ、ヒープ、HTTP/APIステータス、CPU周波数を確認できます。パスワードは出力しません。

2026-09-12にv1.1.1のボードビルド、既存ホストテスト、USB書き込み・ハッシュ照合を確認。実機の起動、自宅Wi-Fi接続、HTTPS応答（HTTP 200/API status=5）、通信後の80MHz復帰をUSB診断で確認しました。APIメンテナンス中のためレート取得は未確認です。画面の実表示、iPhoneテザリング、電池持続時間は未検証です。

### v1.1.1の接続修正

80MHzでのTLS鍵交換中にCPU 0のウォッチドッグが発動し、Wi-Fi接続後に再起動する不具合を修正。HTTPS処理中のみ240MHzへ上げ、クライアントの終了処理後に元の周波数へ戻します。証明書検証とウォッチドッグは有効のままです。

実機回帰確認（pyserialが必要。USBポートを開く際に本体が再起動する場合があります）：

```sh
rtk proxy python firmware/test/serial_connection.py <確認したポート> 45
# APIがメンテナンス中の場合のみ、HTTPS疎通の検証として実行
rtk proxy python firmware/test/serial_connection.py <確認したポート> 45 --allow-maintenance
```

通常モードはレート取得済み状態を3回以上確認します。メンテナンス許容モードはHTTP 200、API status=5、CPU 80MHzへの復帰を確認し、レート取得成功とは区別します。どちらも異常終了・繰り返す再起動を検出したら失敗します。
